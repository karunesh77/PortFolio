HOW I BUILT HIREMITRA WITH NEXT.JS & EXPRESS

Karunesh Gupta • Jan 15, 2025

HireMitra started as an idea to simplify the job search process for blue-collar workers in India. The existing platforms were either too complex or not designed for the local market. I wanted to build something that workers could use with minimal friction — search jobs, apply, and communicate with employers directly.

The challenge was clear: build a platform that serves two completely different user types — workers looking for jobs and employers posting them — with a clean, intuitive interface that works on low-end devices.

THE TECH STACK DECISION

I chose Next.js for the frontend because of its SSR capabilities — job listings needed to be SEO-friendly and fast-loading. The App Router gave me clean layouts for the worker dashboard vs employer dashboard without duplicating code.

For the backend, Express.js with MongoDB was the natural choice. The schema-less nature of MongoDB worked perfectly for job listings where different categories have different fields. A construction job has different requirements than a delivery job.

AUTHENTICATION FLOW

The auth system uses JWT with refresh tokens. When a user logs in, they get an access token (15 min expiry) and a refresh token (7 days). The access token is stored in memory, the refresh token in an HTTP-only cookie. This prevents XSS attacks while keeping the UX smooth.

I implemented role-based access control with three roles: worker, employer, and admin. Each role has different API permissions enforced at the middleware level. The Auth Context in React wraps the entire app and provides login state to every component.

THE MESSAGING SYSTEM

This was the hardest part. Workers and employers need to communicate in real-time about job details. I built 8 controller functions handling everything from creating conversations to sending messages to marking them as read.

The message schema stores sender, receiver, conversation ID, content, and timestamps. I used MongoDB's change streams initially but switched to polling for simplicity — most conversations aren't time-critical enough to justify WebSocket complexity.

DEPLOYMENT ON AWS

The frontend is deployed on Vercel with automatic deployments from the main branch. The Express backend runs on an EC2 instance behind Nginx as a reverse proxy. MongoDB Atlas handles the database — their free tier is generous enough for a project this size.

Images (profile photos, job images) go to S3 with CloudFront CDN in front. This keeps the load times fast even for users on slow connections.

LESSONS LEARNED

Building HireMitra taught me that architecture decisions made early compound over time. Choosing to separate the API from the frontend meant I could scale them independently. Using JWT with refresh tokens added complexity upfront but saved countless hours debugging session issues later.

The biggest takeaway: ship early, iterate fast. The first version of HireMitra looked nothing like the current one. User feedback shaped every major feature — the messaging system, the filter bar, the dashboard layout. Build for real users, not imaginary ones.
